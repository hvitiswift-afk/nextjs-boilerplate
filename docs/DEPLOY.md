## Static-versus-server boundary

GitHub Pages publishes static files. It does not execute Next.js server routes or `/api/*` handlers.

Static-compatible outputs include:

- HTML, CSS, JavaScript, images, and documentation;
- generated project portals;
- client-side applications;
- public-safe receipts and release indexes;
- static exports generated by GitHub Actions.

Server-dependent functions must follow one of these states:

```text
SOURCE_VERIFIED_NOT_PUBLICLY_EXECUTED
SIMULATED_IN_ACTIONS_OR_TESTS
REDESIGNED_STATIC_OR_CLIENT_SIDE
EXPLICIT_EXTERNAL_PROVIDER_EXCEPTION_WITH_SEPARATE_EVIDENCE
```

An API source path is not a live Pages API.

## GitHub distribution

Use GitHub-native distribution before considering another provider:

- **Artifacts** for workflow outputs, reports, test fixtures, and build bundles;
- **Releases** for versioned public packages and immutable release notes;
- **Packages** for reusable package/container distribution where supported;
- **Pages** for public static surfaces.

Every distributable must preserve source commit, workflow run, digest, boundaries, and publication state.

## Claims boundary

GitHub source, Actions, artifacts, releases, and Pages each prove different facts.

Never treat any one of them as automatic evidence of:

- public deployment outside its verified URL;
- live server/API behavior on Pages;
- external provider acceptance;
- consent, contract, order, payment, revenue, work start, or delivery;
- partnership, affiliation, grant award, or legal authority;
- independent ChatGPT operation.

## Launch rule

```text
Build in GitHub.
Verify in Actions.
Distribute through GitHub.
Publish static surfaces through Pages.
Read back the public URL.
Receipt only what is proven.
```
